# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Dezin Glass fidelity

- Exact source fidelity is blocking: do not substitute approximate optics, component dimensions, parameters, motion, or styles.
- Reject visible aliasing, dark seams, stale filters, and parameter changes that stall or crash the page.
- Validate against the captured source at matching desktop/mobile viewports before handoff.
- The Switch, Slider, and Toggle demos inside "A family of components" are user-approved and frozen. Preserve their component anatomy, optics, dimensions, parameters, motion, and styling. The QR and video demos are not approved and must match the source WebGL implementations.
- Updated component acceptance criteria supersede the prior freeze: Switch thumb expands into pure glass while held and magnifies the track fill; Slider grabs the pointer immediately, keeps its value readable through glass, and squashes by handle velocity; Toggle pill spring-follows the active item, stretches in motion, magnifies synchronized content, and reveals brand color from gray icons under the glass.
- For Switch and Slider, the production Dezin page implementation is the final authority. Do not translate behavior descriptions into invented UI such as an added numeric value layer or substitute approximate spring/tween state machines.
- Video glass-button circle edges must remain smoothly antialiased: SDF coverage must attenuate displacement, blur, adaptive tint, and specular together; never apply full-strength displacement inside only the partial-coverage edge band.
- The Demo page is Chinese-only and brand-neutral: remove visible Dezin names, logos, encoded URLs, app imagery, and English UI copy. The segmented control must support mouse press-drag switching across visible tabs while preserving click and keyboard behavior.
- Segmented press-drag switching must keep the ordinary pointer cursor; never show grab/grabbing cursors. Keep the QR center icon geometrically centered through every 3D rotation state.
- Segmented appearance follows the current iOS 27 control model: the selected pill is a very light neutral transparent-gray highlight at rest, never a colored fill, border, or shadow; its selected icon keeps that item's own colors. Non-selected hover uses an even lighter neutral background. Only press/drag morphs the pill into glass. A stationary press reaches the maximum vertical height, about 148% of the tab group. As movement speed increases, the glass must stretch horizontally and compress vertically; as speed falls, its height returns toward the stationary maximum. At maximum speed it must still remain slightly taller than the group, around 112%. On release, immediately spring the fixed vertical boost back to the tab height alongside travel deceleration; never hold it until the opacity fade. Pointer speed must visibly drive strong expansion and horizontal stretch. On fast travel and braking, preserve volume-like squash/stretch: horizontal elongation pairs with vertical compression, target overshoot then produces horizontal recoil and vertical bounce. At high-speed arrival, the leading edge must feel as if it hits the destination: keep most velocity stretch trailing behind it, soften forward center overshoot, and retain only a short rebound instead of letting the full symmetric lens spill far beyond the first or last tab. After the first contact, rebound velocity must not re-excite fresh deformation; allow one clean recoil, then damp width, height, and optical-center bias smoothly to rest without sticky micro-oscillations. A click transition must visibly run current-position expansion -> elastic glass travel to the clicked tab while shrinking during the second half -> collapse to the gray highlight. Travel and collapse must overlap and preserve one continuous travel velocity; never jump, restart the travel spring, or wait until arrival before shrinking. Use analytical mass/stiffness/damping springs that preserve velocity across retargeting and carry gesture release velocity into settling; never restart a hand-written spring at zero velocity. Keep travel near Apple's documented 0.5s, moderate-bounce physical range rather than a fast easing-like response. Keep glass visibility separate from shape deformation and begin the final optical attenuation once shape collapse has settled and positional motion has entered its low-amplitude tail, before the travel spring is fully at rest. Freeze significant lens geometry changes first. Treat the transparent-gray selection as the glass's persistent base material: place it fully underneath before the final stage, then attenuate only the refraction/chroma/specular optical layer; never crossfade by making glass disappear while separately making the base material appear. Drive both layers directly with compositor-bound MotionValues, not a per-frame CSS custom property. During the optical attenuation, selected text and icon colors must match across the interactive base, glass base, and refracted layer; never flash black -> gray -> black. During drag, the lens must track the pointer directly and use nearest-segment hit testing so gaps and restarted springs never make it feel sticky. At both edges, the destination anchor remains exactly on the first/last tab center; only live velocity stretch may bias the rendered optical center backward so the leading edge does not spill unrealistically past the track.
- After first contact, compress residual center displacement in both directions so the remaining energy reads primarily as shape recoil, never as a slow positional crawl back to the selected tab.
- A captured mouse pointer is not an active drag until it crosses the movement threshold. A stationary long press must settle once into a stable expanded-glass state and must not keep re-exciting velocity deformation or twitching while held.
- Restore the stationary-hold Q-bounce with an explicit one-shot impact script (arrival impulse plus phase-specific stiffness/damping), not by reopening continuous velocity feedback. Short-click behavior stays independent and unchanged.
